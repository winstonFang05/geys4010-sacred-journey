# 尋聖之旅網站方向與功能規格

2026-11-03 · 首版設計記錄  
2026-11-17 · 補充現有 demo 架構；按新需求修訂真實地圖、地點詳情、線上投稿、評分排行、分享圖片及後台統計

## 1. 要解決的問題

當村校、老店、村落和民間文化空間改變或消失，使用者即使找到地名和年代，也難以知道這個地方對街坊有甚麼意義。網站把可追溯的資料和有公開許可的社區回憶並排整理。項目名稱保留「尋聖」，範圍涵蓋日常文化與社區歷史，屬非宗教計劃。

主要讀者是香港的年輕人、新來港人士，以及對地方歷史有興趣的公眾。居民和場地管理者同時是知識提供者，也是決定如何呈現故事、是否公開位置及是否適合到訪的人。

## 2. 訪客路徑

1. **找地方。** 在首頁真實地圖縮放、移動及點選地點標記，進入該地點的完整故事詳情頁；也可從「沿着地方，讀故事」的熱門三處、搜尋或分類進入。地圖與列表仍為同等入口，不新增地區專頁。
2. **讀故事與規劃到訪。** 詳情頁閱讀照片、基本資料、歷史背景，以及有資料時的建築特色和相關故事；保留資料來源、待核事項和最近審核日期。查閱經核實、獲准公開的 GPS 及附近交通站點，按「查看前往路線」開啟外部地圖軟件。
3. **評價與分享。** 詳情頁最下方免登入提交總體 1–5 星及選填文字評價；左上方的分享按鈕下載該地點預先製作、帶詳情頁 QR 碼的分享圖，供使用者自行發布至社交媒體。
4. **留線索。** 「分享線索」改為開啟外部 Google Form 或具同等能力的問卷。使用者選擇新增地點或補充既有地點，只填相關路徑，再填公共部分；提交不會直接公開。項目團隊及 HKSS 完成審核後才刊登。
5. **從現場回到故事。** 分享圖 QR 碼可直接返回對應地點。日後若在實體場地放置 QR 碼，仍須獲場地同意；導賞活動待確認後才另行上架。

## 4. 網站架構與頁面／區塊

採用「保留單一首頁及原有區塊＋完整地點故事詳情頁＋外部投稿表單＋登入後才可用的管理統計頁」。詳情頁是可獨立閱讀和分享的頁面視圖，不再是彈窗；可沿用 hash 路由，毋須每個地點建立獨立 HTML 檔案。

沿用 `#story/{id}` 路由格式，依 `stories.js` 中實際存在的地點 ID 開啟完整詳情頁；正式收錄且仍存在的地點保持 ID 穩定，避免舊連結和 QR 碼失效，不要求保留已移除的臨時樣例。語言參數仍放在 `#` 之前。下表錨點均相對網站根網址。

### 4.1 地點 ID 與舊連結

以下三個地點僅為臨時樣例，用於示範資料欄位、地點 ID 與連結格式，不代表最終網站會展示或必須保留這三個地點。最終網站的地點名單、數量及各地點資訊完全以 `stories.js` 中的地點記錄為準；地圖標記、故事列表、搜尋與分類、詳情頁及相關故事連結均依該檔案生成，不在介面或路由中硬編碼這三個樣例。原有位置核實、公開精度及內容審核規則維持不變。

「熱門三處」只規定首頁展示至多三個地點，並非全站固定收錄三個地點；候選地點來自 `stories.js`，評分後台只按地點 ID 提供評分資料，不另行決定收錄名單。樣例如已從 `stories.js` 移除，不再顯示，原樣例連結依未知／已下架地點流程處理，不為維持樣例連結而保留內容。

| 樣例編號 | 樣例地點 ID | 樣例繁中標題 | 樣例地區 | 樣例分類 | 樣例詳情目標 |
| --- | --- | --- | --- | --- | --- |
| 01 | `tin-chun` | 尋找天真幼稚園 | 新界・坪輋一帶 | 村校記憶 | `#story/tin-chun` |
| 02 | `ngau-chi-wan` | 牛池灣村的記錄 | 九龍・牛池灣 | 村落與重建 | `#story/ngau-chi-wan` |
| 03 | `ap-lei-chau` | 從大街走到舊碼頭 | 港島南區・鴨脷洲 | 水岸生活 | `#story/ap-lei-chau` |

僅以臨時樣例示範：繁中網址格式為 `https://winstonfang05.github.io/geys4010-sacred-journey/#story/tin-chun`，英文為 `https://winstonfang05.github.io/geys4010-sacred-journey/?lang=en#story/tin-chun`；只有 `stories.js` 仍包含 `tin-chun` 時才顯示該地點。其他地點以其實際 ID 生成連結。排名改變不改寫已收錄地點的 ID 或顯示編號。表單「遺跡類型」是投稿欄位，與網站故事分類分開儲存，不直接取代原有分類。

### 4.2 詳情頁內容與連結

| 位置／內容 | 要求 | 操作與目標 |

GPS、附近站點和照片是新增資料需求，適用於 `stories.js` 中實際收錄的地點；如沿用舊資料，不能直接用原 SVG 百分比位置換算成精確坐標。尚未核實或不宜公開的位置，標示「位置待核實／不公開精確位置」，不提供誤導導航。已核實且獲准公開的地點才啟用路線按鈕。新版以補齊這些資料為驗收前提，不能以佔位坐標或無授權照片冒充完成。

## 5. 互動規則與狀態

### 5.1 搜尋、分類、熱門三處與地圖

- 保留原有即時搜尋及單選分類互動；分類選項依 `stories.js` 中實際地點的分類資料生成，另保留「全部故事」。村校記憶、村落與重建、水岸生活僅為現有樣例分類，不要求最終資料維持這三類；不新增搜尋提交頁。
- 保留搜尋欄位：中英文標題、中英文地區、中英文分類名稱，以及目前顯示語言的摘要；不搜尋完整正文或外部來源文件。
- 保留去首尾空白、NFKC 相容字元正規化、忽略英文字母大小寫及連續字串比對；不提供模糊搜尋或多關鍵字分詞。搜尋與分類同時生效。
- 未輸入搜尋且選「全部故事」時，按 5.5 的排名規則顯示全站最高分三處；搜尋／分類後，顯示符合條件中排名最高的至多三處。
- 結果數量標明「共 X 處符合，顯示最高評分的 Y 處」，避免把三張卡片當成完整資料庫。少於三處則全部展示；沒有結果則保留原有無結果提示。
- 清空搜尋並選「全部故事」回復全站熱門三處；沒有獨立重設按鈕。
- 地圖顯示所有位置可公開的地點，不隨列表搜尋／分類隱藏；被列表篩掉的地點仍可從地圖開啟。數量日後增加不固定為三個標記。
- 搜尋、分類只保留在目前頁面／返回狀態中，不加入網址；同一分頁由詳情返回時保留原條件及捲動位置。重新整理首頁後仍回到初始條件。

### 5.2 真實地圖、詳情與返回

- 以可顯示多個自訂地點標記的真實互動地圖取代 SVG 示意圖，支援手機縮放／移動及桌面操作；保留地圖服務要求的來源署名。
- 地圖供應商及圖磚方案於實作前選定，須支援上述互動、固定地點連結和正式網站使用；本 brief 不擅自指定需付費的地圖方案。嵌入地圖與外部路線軟件可使用不同供應商。
- 點標記或卡片直接進入完整 `#story/{id}` 詳情頁；直接載入或刷新有效故事網址也能正常顯示。
- 不再使用關閉彈窗／Escape 作為返回操作；詳情頁提供「返回地圖／返回故事檔案」，保留同分頁進入時的搜尋、分類、來源及捲動位置。直接進入詳情網址而沒有來源狀態時，返回故事檔案。
- 瀏覽器上一頁／下一頁應與頁面視圖一致。未知／已下架地點顯示清楚提示和返回檔案入口，不能留白。
- 地圖載入失敗時保留列表入口與重試提示，不阻止讀故事。
- 外部路線首版提供 Google Maps 通用路線連結，例如 `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}`；參數須正確編碼。可再增加其他地圖軟件，但不作首版必需項。Google Maps URLs 本身不需 API key，與嵌入地圖所需設定不同。[Google 官方 Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)
- 路線入口在新分頁／地圖 App 開啟，由使用者在地圖軟件選起點與交通方式；不承諾一定啟動原生 App，也不把路線建議等同獲准進入場地。

### 5.3 繁中／英文

- 保留預設繁中、`?lang=en` 開啟英文；其餘值採繁中。按鈕仍為「EN／繁中」，網址參數可隨連結分享，不另存語言偏好。
- 切換更新導覽、主頁文案、分類、卡片、提示、地圖輔助文字，以及目前詳情頁的全部雙語內容與評價表單介面；保留地點 ID、當前頁面、搜尋及分類。
- 搜尋摘要只比對目前語言，換語言後結果數量可能改變。使用者原文評價不自動翻譯。
- 外部投稿表單按本次要求統一使用簡體中文；兩種網站語言均連到同一表單，入口明示「簡體中文表單」，不宣稱已有英文問卷。
- 分享圖片按目前網站語言選擇預製版本，QR 碼指向同語言、同地點詳情頁；兩個版本未齊備時須明示可用語言。

### 5.4 分享線索與審核

- 將原「下載草稿模板」改為「提交地區故事」，新分頁開啟正式表單填答網址，不連到編輯網址。原 TXT 模板停止作為主要入口。
- 表單連結以可設定欄位 `contributionFormUrl` 管理；目前未提供真實表單網址，上線前須建立、發布和測試。未設定時明示「表單準備中」，不可用虛構連結或空白按鈕冒充完成。
- 問卷全文、分支及設定見第 9 節。Google 帳號登入是表單檔案上傳要求，與本站免登入評分分開。
- 回覆及附件先存表單管理者的受限工作區，按「新收件 → 待核實／待補充 → 項目團隊及 HKSS 審核 → 可發布／不發布」管理；雙方審核通過且核實使用權、來源、公開位置後，才人工整理至網站。
- Google Forms 接受回覆不等於兩方完成審核，也不自動新增地圖標記。本站不聲稱能得知外部表單是否完成提交；如需可靠收件數，另從表單回覆取得，不用按鈕點擊代替。

### 5.5 免登入評分、評價及熱門排序

- 在每個詳情頁最下方提供單一總體 1–5 星評分，必填；1 星為最低，5 星為最高。文字評價選填，提示可描述值得到訪程度、文化特色或故事吸引度，這些是寫作提示，不另設三個評分維度。
- 不要求登入、Email 或真實姓名；評價以匿名方式顯示。提交前提示不要留下私人資料或未經證實的指控。建議文字上限為 1,000 字，前後端一致驗證。
- 每個瀏覽器以隨機匿名識別碼對每個地點保留一筆有效評分，可更新自己的評分及評語，更新不新增票數。此識別碼只用於評分去重，不用來計算訪客人數。
- 服務端執行星數範圍、字數、重複請求及頻率檢查；同一提交請求重送不得多計。清除瀏覽器資料、換瀏覽器或換裝置仍可能重複投票，不能保證一人一票，不以 IP 地址直接判定唯一使用者。
- 有效星數成功寫入後納入平均分；文字評語先顯示「待審核」，管理者通過後才公開。被判為垃圾或違規的整筆評價可停用，停用分數同時排除於平均和排名；只有文字被隱藏但星數仍有效時則保留分數。
- 地點平均分＝該地點全部有效評分的星數總和 ÷ 有效評分筆數；顯示一位小數，排序使用未四捨五入原值。每張熱門卡片及詳情頁顯示平均分與筆數，並說明屬使用者意見，不是官方文化價值評級。
- 全站熱門三處先按平均分由高至低；同分按有效評分筆數由多至少；仍同分按固定地點 ID 升序，確保結果穩定。首版不設最低票數，單筆高分可能居前，故必須同時顯示票數。
- 有評分地點不足三處時，以固定 ID 順序補入未評分地點並明示「尚未評分」，不給假星數；完全沒有評分時展示三處待評分地點並說明「暫無評分排行」。地點不足三處則全部顯示。
- 提交或更新成功後重新取得平均分及排行；失敗時保留輸入、顯示重試，不以本機假資料宣稱已成功或已計入全站排名。重新整理、換裝置應讀取同一後台彙總結果。

後台名稱使用「瀏覽次數」「分享圖片下載次數（下載觸發）」；不稱為瀏覽人數、分享人數或實際社交分享量。不記錄獨立訪客數、不估算一人幾次，不因匿名評分識別碼存在而新增人數指標。
